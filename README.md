# js-code-analysis

A Claude Code skill that analyzes a JavaScript/TypeScript project and writes one AI-readable report, `CODE_ANALYSIS_REPORT.md`, with a ranked list of what to test and refactor. It is the JS counterpart of the `csharp-code-analysis` skill.

It combines:

- **Complexity** from [FTA](https://ftaproject.dev) (Fast TypeScript Analyzer, [sgb-io/fta](https://github.com/sgb-io/fta)): per-file FTA score, cyclomatic complexity, size.
- **Unit test coverage** from the project's own runner: Vitest (`@vitest/coverage-v8`), Jest (built in), or c8 wrapped around the test command for mocha, `node --test`, ava and unrecognised runners.
- **Function-level detail** derived from the coverage data: functions no test calls, approximate per-function complexity, uncovered lines, and which test files touch each source file.

## Layout

| Path | What it is |
|---|---|
| `skill/SKILL.md` | The skill instructions Claude follows (check → warn about installs → run → relay) |
| `skill/scripts/analyze.mjs` | The analyzer CLI (Node 18+, no npm dependencies) |
| `skill/scripts/lib/` | `detect` (runner/coverage/package manager), `files` (source discovery, test map), `fta`, `coverage` (run tests, parse istanbul JSON), `findings` (severity rules), `report` (markdown) |
| `skill/references/` | Report format and the remediation guidelines embedded in every report |
| `skill/vendor/` | Bundled FTA binaries (macOS + Linux) and c8 with its dependencies; generated by `scripts/bundle.sh` |
| `skill/THIRD_PARTY_NOTICES.md`, `skill/licenses/` | Licenses of the bundled third-party software |
| `scripts/bundle.sh` | Refreshes `skill/vendor` (`--all-platforms` adds Windows and 32-bit ARM FTA binaries) |
| `scripts/install.sh` | Copies `skill/` to `~/.claude/skills/js-code-analysis` and writes `VERSION` |
| `test/` | Unit tests, end-to-end tests, and fixture projects (vitest-ts, jest-js, mocha-js, node-test, no-tests) |

## Dependencies

Nothing is fetched at analysis time. npm is only used by `scripts/bundle.sh`, once, to vendor:

- `fta-cli@3.0.1` prebuilt binaries (MIT), run directly instead of through npx;
- `c8@12.0.0` and its production dependencies, run with the current `node`.

The one thing that cannot be bundled is Vitest's coverage provider: it has to be installed in the analyzed project at the same version as that project's Vitest. The analyzer detects this (and a missing `node_modules`), prints the exact command, and refuses with exit code 3 until it is run with `--install`. The skill tells Claude to ask the user before passing `--install`.

## Usage

```bash
npm run bundle          # once, or after bumping versions in scripts/bundle.sh
npm run install-skill   # installs to ~/.claude/skills/js-code-analysis
npm test                # unit + end-to-end tests (no network needed)
npm run analyze-self    # dogfood: analyze this repo's own scripts
```

Direct use:

```bash
node skill/scripts/analyze.mjs <project> --check      # what would be installed; changes nothing
node skill/scripts/analyze.mjs <project> --install    # full analysis, allowed to install
node skill/scripts/analyze.mjs <project> --skip-tests # complexity only
node skill/scripts/analyze.mjs --help
```

Thresholds and severity rules live in `skill/scripts/lib/findings.mjs` (`THRESHOLDS`) and are documented in `skill/references/report-format.md`; keep the two in sync.
